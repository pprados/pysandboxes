# Threat model

## What this project does and where untrusted input enters
- PySandboxes runs Python code its caller does not trust, for example code generated by an LLM. Two layers: guards that
  patch the Python API (files, network, imports, environment, sensitive calls, `eval`/`exec`/`compile`), and an OS
  boundary chosen through a provider (`landlock`, `bwrap`, `firejail`, `unshare`, `qemu`).
- The sandboxed code is the attacker. Also untrusted: what it sends over the local SSE channel to the host process
  (the transport, including the restricted unpickling), and any string it passes to `eval`, `exec` or `compile`.
- The `.py-sandboxes` rule files are trusted: a permissive file is a configuration mistake, not a defect.

## Components that matter most / least
- Most: `pysandboxes/_os_sandbox.py` and the providers (escape from the namespace, the guest reaching the host under
  `qemu`), `pysandboxes/remote/` (the SSE transport and the restricted unpickle), `guard_files`, `guard_socket` (DNS
  pinning), `guard_import`, `guard_api`, and the `eval-*` sub-language (`eval_rules.py`, `eval_transform.py`,
  `eval_runtime.py`).
- Least: `samples/`, `scripts/`, `wiki/`, tests.

## How to exercise it
- `uv run pytest tests/unit_tests/` for the unit tests; `tests/integration_tests/` for remote execution.
- `make security-corpus` runs the known attack regression corpus.
- The `python-sb` command line runs a script under a sandbox. Providers other than `none` and `subprocess` need Linux
  kernel features (user namespaces, landlock) that may be missing in the scan environment: say so rather than report
  a provider as broken.

## How you rate severity
- Critical: sandboxed code escapes the OS boundary of a kernel-backed provider while the Python layer is configured
  to hold, or runs code in the host process.
- High: sandboxed code reads, writes or deletes a path no rule allows, connects to an address no rule allows, imports
  or calls an API the rules deny (including through `eval`, `exec`, `compile` or `pickle`), or widens its own
  permissions through a rule file or learning-mode output.
- Medium: an `eval-*` budget or timeout that cannot be enforced, leaving the host process stuck or exhausted.

## Anything to leave alone
- Do not report the weaknesses already documented in `wiki/weaknesses.md`, `wiki/audit-eval-security.md` and
  `wiki/audit-python-security.md`, unless the mitigation described there is defeated.
- Undoing a monkey patch from inside the interpreter is expected: the Python layer is friction, the OS layer is the
  boundary.
- `none` and `subprocess` provide no OS boundary by design, and `py-sandbox=False` switches the Python layer off on
  purpose.
- What a technology cannot express, as listed in `wiki/os-providers.md` (for example `landlock` denies a path but
  cannot hide it).
- `SECURITY.md` is the authoritative list of what counts as a vulnerability.
